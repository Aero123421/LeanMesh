# HIL 2026-10-03: transfer between two networks (docs/07 §8)

Bench: network A = S3 root (`usbmodem1101`, the replacement root of docs/hil/2026-10-03-root-replacement.md, term 20);
network B = XIAO ESP32-C6 as root (`usbmodem3`, `scripts/hil.sh flash root ... esp32c6`; the first C6 root of this bench);
moved leaf = C3 (`usbmodem1301`, leaf-c3c, ACTIVE in A at assignment 1). One Host process per root (A: `lm.sock`, B:
`lm-netB.sock`). Firmware: main bc252f8.

## Run

1. `hil.py init --name netB`, `provision root --port /dev/cu.usbmodem3 --net netB`: the C6 made its key and came up as
   root of B; Host B paired, took a backup (sequence 1) and read policy EXTERNAL.
2. `hil.py transfer leaf-c3c --to netB` (mode 0): nonce from the board, fleet ticket A -> B (expected_old 1, new
   generation 2, 375 B), installed on the board (APPLIED), `join transfer`, approval through Host B: leaf-c3c ACTIVE in B at
   assignment 2 - 8.7 s for the whole command. Host B send: RECEIVED, END_VERIFIED. Root A was up all the time.
3. `hil.py reconcile leaf-c3c` (the same ticket to root A through Host A): **refused by Host A** with
   `the signed object names another domain than the request` - the ticket is signed for its target domain B. Fixed in
   this change (the source domain's Host accepts a type-3 ticket whose source is its domain). With the fix: APPLIED;
   Host A lists the device UNASSIGNED.
4. Host A send to the moved device: the root accepted it (ROOT_ACCEPTED, ROOT_PERSISTED) and it stays SENDING (no session,
   no deadline). It is never delivered, but it is not refused either - unlike a revoked device (HIL-F6). Filed as an issue.

## Not verified here

- Mode 1 (`--grant`), PREAPPROVED at the target, and a move while root A is off.
- A -> B -> A.
